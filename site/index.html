Why this one

Five things here that you would otherwise spend months learning the hard way.

Two reviewers who cannot cover for each other

Every agent pull request is reviewed twice — and the second reviewer runs on a different model family, because a second draw from the same distribution shares the same blind spots. A referee then reads both reviews and the diff and rules on the disagreements, so you are handed an answer instead of an argument.

Every bug it has ever had is now a test

128 hard-won operational lessons are pinned in place, inside a suite of 626 tests that runs on every pull request. When something breaks once, the reason it broke is welded into the suite — so the system cannot quietly slide back into a mistake it has already made. Most agent setups forget. This one cannot.

It cannot fail quietly

A dead agent and a healthy agent must never look the same. A missing optional credential downgrades a check and says so out loud; it never fails your pull request. A missing input never reads as "nothing to do". Silence is treated as a defect, everywhere, on purpose.

No vendor lock-in — enforced by a test

Workflows and prompts address models by role — judge, execute, challenge — never by name. One small adapter file per provider holds the vendor-specific bits, and the build fails if a vendor name leaks anywhere else. Switching providers is a config edit, not a migration.

It remembers what it learns

A "second brain" lets the agents distill their own operational lessons into short, indexed cards — read cheaply at the start of every run, written only by one agent in a self-gated retrospective, and never live until a human merges the card. Five more scheduled agents build on it: dependency upgrades, docs freshness, backlog grooming, floor raises, release drafts — each opt-in, each reviewed the same way as everything else.

Start in three steps

The interview is local text substitution — no network calls, finishes in seconds.

  1. Create your repo from the template

    Then run the adoption interview. It asks for your product name, provider, models and alert channel, rewrites every placeholder, and prints exactly what is left to do by hand.

    tools/init.sh

  2. Add one credential

    Normally your agent CLI's subscription token, not an API key — so runs cost nothing beyond the flat monthly plan you already pay for. The repo tells you the exact command to mint it.

    tools/run-agent.sh --check-credentials <agent>

  3. Watch one loop, then merge it yourself

    Open an issue against the bundled example and watch the whole loop run — triage, pull request, both reviews, the gauntlet. Then click merge. That is the entire system, proven before any of your own code exists.

Two things worth knowing up front

Nothing surprises you on day one

All ten scheduled agents ship disabled, and every quality floor ships uncalibrated — measured against your code, never someone else's finish line. You dry-run each agent, then switch them on one at a time. No cron firehose, no surprise bill.

The cost is honest

The steward, the reviews and every scheduled run sit on your existing agent-CLI subscription, so one more run costs nothing. The only per-token spend is the optional second reviewer, which needs its own key. Skip it and you lose a second opinion — never the system.
